# Native offline workbench

Created by Jason Stys · [Source and contact](https://github.com/JasonStys).

## Launch and select actual project inputs

The Windows portable EXE bundles patched Python 3.14.10, Tcl/Tk 9.0.4 and the complete graphical project workflow. It needs no Python/Node installation, terminal setup, account or baked password. It is a portable app, not an installer, code-signed executable, production certification or cross-platform binary.

Choose **Inputs and analysis**, select the operation, browse authorized supported local inputs and configure the visible parameters. Acknowledge permission and use **Run analysis**. Changes clear acknowledgement; missing files are not silently replaced by a prepared case. Fictional prepared scenarios are optional inputs inside this same full app, not a separate demo application. No automatic model, provider, collector or enforcement operation is available.

## Review, export, reopen and retain

Choose a named view in **Findings and timeline**, search literal evidence and select a row for its full structured record. Table cells are compact; all original retained bytes remain exportable even when the visible table is capped at 5000 rows. A denied proposal, mismatching label or inconclusive observation remains review evidence, not an application failure or approval. Invalid source data cannot replace an earlier completed bundle.

Export creates a new private directory containing the exact retained files; it never overwrites an existing destination. **Saved analyses** reopens verified immutable bundles without rerunning their inputs. Removal is explicit, confirms the exact current bundle and does not delete original inputs or earlier exported copies. There is no automatic eviction or forensic-erasure claim. Help, actual runtime notices and **Exit application** remain accessible; normal exit waits for the one owned non-daemon worker and closes SQLite.

## Admission, policy changes, continuity and direct graph

Choose an offline closed-schema policy and labeled admission cases, and set the explicit **synthetic clock tick**, not today's timestamp. The actual engine checks direct transport and fresh in-memory MAC proof fixtures. The single-hypothetical-flow operation exposes workload names, TCP/UDP, port and a closed proof-fixture choice. An allowed TCP edge can still have denied identity/posture admission. These are dummy issuer proofs, not mTLS/certificates or real traffic.

Compare two policies for exact effective added/removed direct permissions and possible application pivots. Continuity uses owner-authored direct allow/deny requirements at every validity/exception boundary and just-before tick in at most 3600 ticks. Requirements never grant an exception or renew expired policy; required connectivity loss stays in the owner queue. The original labeled cases may mismatch after an intentional policy/clock change; that discrepancy is retained for review.

**Saved direct graph** draws only actual effective direct TCP edges from the same parsed policy/hash as the report; transitive application pivots never become direct arrows. In continuity the graph explicitly represents the final interval tick. Full original matrix, workload inventory, edge data and pivots remain selectable. Long node names are compacted on the diagram; full names remain in inventory/matrix records. This is a saved policy projection, not a live network display, route/session simulation or operational monitoring.

Every original per-workload `.nft` file remains exportable as data. Do not apply them to a workstation. The native UI never invokes firewall, namespace, networking, discovery or privileged commands. The existing explicitly opted-in isolated hosted Linux kernel packet lane stays separate and does not run on this PC.

## Local data, runtime and reproducible validation

The version-independent default profile is `%LOCALAPPDATA%/JasonStys/ZeroTrustSegmentationLab`, outside the installation/Git checkout. Markers refuse unknown nonempty or linked paths instead of resetting data. The exclusive process lock, SQLite foreign keys/FULL synchronization and original-byte hashes protect application consistency. They do not authenticate another OS-owner process or an administrator, encrypt the data, prove input authenticity or replace private OS permissions. History and exports are plaintext: keep the whole profile private and back it up after clean exit. The original CLI keeps its explicit caller-selected paths.

Retention caps at 20 analyses / 128 MiB payload, 64 MiB per bundle and 32 MiB per file; metadata/SQLite add overhead. Bundles allow at most 24 files, covering all 16 supported workloads:16 original .nft files plus original JSON/HTML and the saved graph (19 files), with unchanged byte caps. Input acquisition uses nonblocking/no-follow descriptors, checks the actual ordinary one-link opened file and exact size, and rejects unsafe links, devices, malformed/oversized records and concurrent byte changes. Actual POSIX no-writer FIFO replacement and Windows NUL-descriptor tests are distinct platform proofs.

Developer recipe on Windows: install `requirements-dev.lock` and `requirements-native.lock` with `--require-hashes`; run `python scripts/build_native.py`, then `python scripts/test_native_app.py`. The source/dirty flag, closed resource hashes and actual runtime DLL identity are recorded; Python/Tcl/Tk and applicable PyInstaller notices are collected from the installed runtime. The consumer runs the actual frozen app twice on a new marked synthetic profile with a restricted environment, drives the same widgets/engines/SQLite, verifies independent domain outcomes, exact export/reopen and normal owned PID exits. Presentation-unit tests are separately labeled and never stand in for this actual EXE proof.

The added Windows job pins Python 3.14.10 and audits its full native lock. Original OS quality, strict 95% combined statement/branch coverage and independent domain/security lanes remain. No package/profile artifact or Actions cache is uploaded; the app makes no background upload or arbitrary user-command/plugin call. Clean committed native identity and hosted checks must be reviewed before release/installation. Historical Word editions keep their exact original source/date meaning.
