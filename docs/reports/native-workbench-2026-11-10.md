# Native segmentation workbench validation

Created by Jason Stys. Windows x64 portable candidate version 1.1.0; observations on 10–11 November 2026. [Native usage and policy meaning](../native-workbench.md).

## Changes and rationale

The actual offline admission, direct transport matrix, policy difference, possible-pivot and dependency-continuity engines now have graphical file/policy/clock/flow controls. The optional prepared cases are inputs in the same full application. Literal findings/full records, exact original exports and durable SQLite history remain available after restart.

A separate saved graph displays only effective direct TCP permissions, computed from the same parsed immutable policy and byte hash as its report. Transitive possible pivots never become direct arrows: web→api→db does not grant direct web→db. The complete TCP/UDP matrix and original workload names remain available. A concurrent continuity-policy replacement is rejected rather than showing one policy's graph beside another report. Continuity labels its graph as the final interval tick, keeping expiry loss visible.

The single-flow operation checks a hypothetical source/target/protocol/port with a closed fresh in-memory dummy MAC proof fixture. Allowed transport can still mean denied identity admission. Owner-authored allow/deny requirements do not grant permissions, renew policy, authenticate a certificate or enforce a network.

## CI and delivery boundary

All original four OS/Python quality, security and explicitly opted-in disposable Linux packet/revocation tests remain. The new exact Python 3.14.10 Windows lane builds and exercises the complete actual EXE without uploading packages/profiles or retaining Actions caches. CodeQL security-extended scope stays unchanged. Local candidate observations do not establish hosted results, a published release or installation; clean committed identity and fresh hosted results are separate prerequisites.

No workstation firewall, namespace, listener, discovery, live traffic, account or Docker operation ran. The GUI has no privileged/native-enforcement path; exported `.nft` files are data and must not be applied to a workstation. MAC fixtures are not actual workload certificates/mTLS; this is not a complete zero-trust architecture, operational monitor or security certification. Windows x64 portable only, unsigned; plaintext OS-owner storage is not authentication/encryption. Historical Office publications retain their original source/date meaning.
